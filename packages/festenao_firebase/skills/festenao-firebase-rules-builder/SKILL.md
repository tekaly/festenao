# festenao_firebase rules builder

A `firestore.rules` file is written here as Dart: `FirestoreRules` collects
functions and match blocks in call order — the order of the file — and
`toRulesText()` prints it. Everything a rule needs is a `RulesExpr`, a typed
expression tree, so a condition is built once and reused instead of being
copy-pasted into a text file. The same object is what the simulator and the
emulator harness evaluate (`festenao-firebase-rules-testing`), and what the
tkcms rule sets assemble (`festenao-firebase-tkcms-rules`).

## Guidelines

* Import `package:festenao_firebase/firestore_rules.dart` (builder,
  expressions, `rulesToText`). Never import `src/`.
* `FirestoreRules()` holds the `rules_version` (`'2'`) and the
  `/databases/{database}/documents` match every rule lives in.
  `headerComment(text)` writes the comments above `service`, `comment(text)`
  and `blankLine()` lay out the documents block, `denyAll()` adds the
  explicit `match /{document=**} { allow read, write: if false; }`.
* `rules.function(name, [params], (f) => expr)` declares a rules function.
  `f.param('name')` is a parameter, `f.let('doc', expr)` a `let` binding
  returned as a variable — bind a `get()` once and test it twice instead of
  paying for two document reads. A duplicate function name throws when the
  file is written.
* `rules.match(pattern, (m) { ... })` opens a block; `m.match(...)` nests one.
  Patterns are `/{entity}/{entityId}` style, `{name=**}` for a recursive
  wildcard. `m.v('name')` is the wildcard bound by the block or one of its
  ancestors, and throws for anything else — a typo is a build error, not a
  rule that silently never matches.
* `m.allow([RulesMethod.read], condition)` where the methods are `read`,
  `write` (composites) or `get`, `list`, `create`, `update`, `delete`. Any
  matching `allow` grants: rules are additive, a narrower block never takes
  back what a wider one gave.
* Expressions: `&`, `|`, `~` (and/or/not), `eq`, `neq`, `lt`, `lte`, `gt`,
  `gte`, `isIn`, `isType`, `isNull`, `isNotNull`, `member(name)`,
  `index(key)`, `get(key, default)`, `call(method, args)`, `ternary`. Plain
  Dart values are accepted where an expression is expected, `lit(value)`
  forces one.
* Shortcuts: `request`, `requestAuth`, `requestAuthUid`, `requestAuthToken`,
  `requestResource`, `requestResourceData`, `resource`, `resourceData`,
  `requestTime`, `requestMethod`, `requestPath`.
* Documents: `docPath([...])` builds
  `/databases/$(database)/documents/...` from literals and expressions,
  `rulesGet(path)` and `rulesExists(path)` read one. `rulesGet` of a missing
  document is `null` — check it before reading a field, and prefer
  `doc.data.get('admin', false).eq(true)` to `doc.data.admin == true`, which
  is an error (hence a denial) on a document that has no such field.
* A rules file is generated, never hand edited: a `tool/generate_firestore_
  rules.dart` writes it (with `--check` for CI), a
  `tool/publish_firestore_rules.dart` regenerates and deploys it. Say so in
  the header comment.

## Examples

### A rules file

```dart
import 'package:festenao_firebase/firestore_rules.dart';

FirestoreRules roomRules() {
  var rules = FirestoreRules();
  rules.headerComment(
    'The chat rooms: a member reads a room and writes its messages.\n'
    'Generated by tool/generate_firestore_rules.dart, do not edit.',
  );
  rules.denyAll();

  var signedIn = rules.function(
    'signedIn',
    [],
    (f) => requestAuth.isNotNull & requestAuthUid.isNotNull,
  );
  var isMember = rules.function('isMember', ['roomId'], (f) {
    // One get(), two conditions.
    var doc = f.let(
      'doc',
      rulesGet(docPath(['room', f.param('roomId'), 'member', requestAuthUid])),
    );
    return doc.isNotNull & doc.data.get('active', false).eq(true);
  });

  rules.match('/room/{roomId}', (m) {
    m.allow([RulesMethod.read], isMember.call([m.v('roomId')]));
    m.allow(
      [RulesMethod.create],
      signedIn.call([]) & requestResourceData.get('owner', '').eq(requestAuthUid),
    );
    m.match('/message/{messageId}', (mm) {
      // roomId comes from the parent block.
      mm.allow([RulesMethod.read, RulesMethod.write], isMember.call([mm.v('roomId')]));
    });
  });
  return rules;
}
```

### The generate tool

```dart
import 'dart:io';

import 'package:my_app_firebase/my_app_firestore_rules.dart';
import 'package:path/path.dart';

/// `dart run tool/generate_firestore_rules.dart [--check]`, from the package
/// root; `--check` only reports (exit code 1 when out of date).
Future<void> main(List<String> args) async {
  var check = args.contains('--check');
  var file = File(join(Directory.current.path, 'firestore.rules'));
  var text = myAppFirestoreRules().toRulesText();
  var existing = file.existsSync() ? await file.readAsString() : null;
  if (existing == text) {
    stdout.writeln('firestore.rules: up to date');
    return;
  }
  if (check) {
    stdout.writeln('firestore.rules: would change');
    exit(1);
  }
  await file.writeAsString(text);
  stdout.writeln('firestore.rules: written');
}
```

### A claim and a time condition

```dart
var isAdmin = rules.function(
  'isAdmin',
  [],
  (f) => requestAuthToken.get('role', '').eq('admin'),
);
rules.match('/event/{eventId}', (m) {
  m.allow([RulesMethod.read], resourceData.get('public', false).eq(true) | isAdmin.call([]));
  // A write must carry a server timestamp.
  m.allow(
    [RulesMethod.write],
    isAdmin.call([]) & requestResourceData.get('updated', null).eq(requestTime),
  );
});
```

## Common mistakes

* Reading a field of a `get()` that may be missing: `doc.data.admin` on a
  document without that field is an evaluation error, which denies the
  operation — `doc.data.get('admin', false)` is what the rule sets use.
* Forgetting that the wildcards of a `{name=**}` pattern are unbound on a
  `list`: a rule reading `m.v('userId')` under a recursive wildcard denies
  queries. Give the self read rules a `get` only (`RulesMethod.get`), as
  `addAccessSelfRules` does.
* Expecting a nested block to restrict its parent: a broader `allow` higher
  up still grants. Narrow the parent instead.
* Hand editing the generated `firestore.rules`: the next generate run drops
  it. Change the Dart and regenerate.
* Counting on more than 10 `get()`/`exists()` per request (20 in a batch or a
  transaction): both the engine and the simulator refuse beyond that.
