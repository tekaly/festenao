# festenao_dartff

The festenao Cloud Functions written in Dart, for the admin sdk runtime
(`firebase.json` runtime `dart3`): `FfApp` (the `FestenaoServerApp` of the
functions), the cms site functions, a standalone local server, the firebase
project files (rules, indexes, emulator ports) and four rules test contexts.

## Getting started

A git package (`publish_to: none`):

```yaml
dependencies:
  festenao_dartff:
    git:
      url: https://github.com/tekaly/festenao
      path: packages/festenao_dartff
```

Platforms: Dart VM only (io: the admin sdk, `dart:io` http servers), never
the web nor Flutter. Locally, everything runs in memory:
[example/main.dart](example/main.dart) serves the functions of a dev `FfApp`
on in memory firebase services and reads a cms site:

```sh
dart run example/main.dart
```

To know:

- Only the callable functions authenticate: the server takes the user id
  from the verified auth context of `onCall`, an https command is anonymous.
- `FfApp(firestoreDocApi: true)` serves the raw firestore doc api (any
  document, admin rights) and lets any signed in user create an app (top)
  entity: `functions/bin/server.dart` sets it only under the emulator
  (`isFunctionsEmulator`). Otherwise only an admin of the server's app
  creates an app entity (its creator becomes an app admin); the first app
  admin is written with the admin rights.
- The emulator tests start the emulator on the project of `.firebaserc`
  (a local, git ignored file), not a `demo-` project.

## Functions

`functions/bin/server.dart` registers, for a dev and a prod `FfApp`:

| Function (dev / prod) | What |
|---|---|
| `commanddartv2dev` / `commanddartv2prod` | the api, http |
| `callcommanddartv2dev` / `callcommanddartv2prod` | the api, callable (authenticated) |
| `ampdev` / `amp` | the amp page |
| `cmsdev` / `cms` | the cms sites of the projects |
| `cmsdemo` (flavor free) | the hard coded demo site of `festenao_demo` |

## Cms sites

`cms[dev]` serves the published pages of the synced content database
`app/<app>/project/<projectId>/data/<dataId>` of a project:

```
https://<hosting>/cms/<projectId>/<dataId>/             index
https://<hosting>/cms/<projectId>/<dataId>/page/<slug>  a page
https://<hosting>/cms/<projectId>/<dataId>/sitemap.xml
https://<hosting>/cms/<projectId>/<dataId>/robots.txt
https://<hosting>/cmsdemo/                              the demo site
```

The app hosting (same firebase project as the functions) rewrites them to
the function of its flavor, before its `**` rewrite:

```json
"rewrites": [
  { "source": "/cms{,/**}", "function": { "functionId": "cmsdev", "region": "europe-west1" } },
  { "source": "/cmsdemo{,/**}", "function": { "functionId": "cmsdemo", "region": "europe-west1" } },
  { "source": "**", "destination": "/index.html" }
]
```

`{,/**}` also sends `/cmsdemo` (no trailing slash) to the function; a
`/cmsdemo` → `/cmsdemo/` redirect loops instead, its source matching both.

The links of a site follow the url the visitor typed (the forwarded host of
the hosting), so the same function also answers at its own url and on a
local runner (`http://localhost:8040/cmsdev/<projectId>/<dataId>/`). An app
customizes its sites with the hooks of `FestenaoServerApp` (`cmsSiteOf`,
`cmsSiteHandler`, `cmsContentSdbOptions`...).

## Build, test

```sh
dart run tool/compile_dart_function.dart   # functions/bin/server (linux x64)
dart test test/ff_app_test.dart test/cms_function_test.dart   # in memory
dart test test/cms_emulator_test.dart      # cms functions, on the emulator
dart test test/emulator_test.dart          # the api, on the emulator
```

`functions/functions.yaml` is generated (`dart run build_runner build` in
`functions/`, or by the firebase cli on deploy).

The rules test contexts, one folder each with its `firestore.rules`
(generated by the `festenao_firebase` presets, as the top `firestore.rules`:
`dart run tool/generate_firestore_rules.dart` in `festenao_firebase`), a
`tool/` emulator starter and one emulator test: `festenao_firebase_api_context.dart` (api + rules),
`festenao_firebase_standalone_context.dart` (the client creates, invites
and joins directly), `festenao_firebase_full_api_context.dart` (deny all,
every access through the api) and `festenao_firebase_no_api_context.dart`
(rules only, no function). Run their tests from their folder
(`dart test`); the emulator ports are shared, one emulator at a time.

The skill `skills/festenao-dartff-functions/SKILL.md` has the details.
